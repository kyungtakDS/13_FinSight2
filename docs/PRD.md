# PRD: FinSight

## 목표

프리랜서·1인 사업자가 카드 명세서 CSV를 올리면 사업 경비 후보를 자동 분류해, 세무사에게 그대로 넘길 수 있는 정리본을 만들어 준다.

## 사용자

종합소득세 신고를 앞두고 카드 명세서에서 경비 처리 가능한 지출을 골라내야 하지만, 수백 건을 직접 분류할 시간도 세무 지식도 없는 사람.

일반 소비자용 가계부(뱅크샐러드·토스)는 마이데이터로 지출을 **보여주지만** "이 지출이 경비인가"에는 답하지 않는다. 그 공백이 이 제품의 자리다.

| | 페르소나 | 빈도 | 성공 조건 |
|---|---|---|---|
| P1 | 종합소득세 신고 앞둔 프리랜서 (핵심) | 연 1회, 파일 여러 개 | 경비 후보와 추정 절감액을 보고 세무사에게 파일을 넘긴다 |
| P2 | 분기 정리하는 1인 사업자 | 분기 1회 | 계정과목별 집계를 그대로 장부에 옮긴다 |

사용자는 카드사 사이트에서 CSV를 직접 내려받아 올리는 수고를 감수하는데, **그 대가가 절세액이기 때문에** 감수한다. 이 교환이 성립하지 않으면 제품이 성립하지 않는다.

## 핵심 기능 (유즈케이스)

흐름: **랜딩 → Google 가입 → 업로드 → 무료 리포트(자기 숫자) → 결제 → 전체 열람·다운로드**

1. **UC-01** 랜딩에서 가치 제안·데이터 처리·결제 조건을 읽는다 — 무엇이 전송·저장되는지, 반복청구·해지·환불 조건, **세무 자문이 아니라는 고지**를 안다
2. **UC-02/03** Google 계정으로 가입·로그인 / 로그아웃. **익명 업로드는 없다**
3. **UC-04** 카드사 CSV 업로드 — 인코딩(cp949/utf-8)과 컬럼 구조를 자동 판별한다. 카드사마다 다른 양식을 사용자가 맞춰줄 필요가 없다
4. **UC-05** 분석 진행 상황 확인 — 탭을 닫아도 잡은 스스로 끝난다
5. **UC-06** **무료 리포트 열람** — 절세 추정액 + 상위 3개 인사이트. 여기서 사용자는 자기 숫자를 본다
6. **UC-07** Pro 구독 시작 (Polar Checkout)
7. **UC-08** **전체 분류 내역 열람** (유료) — 거래별 `사업 경비 / 개인 지출 / 애매` 판정과 **판정 근거 한 줄**
8. **UC-09** **시계열 대시보드** (유료) — 계정과목별·월별 추이
9. **UC-10** **세무사 전달용 파일 다운로드** (유료)
10. **UC-11** 과거 업로드 목록에서 하나 열기 — 기간·거래 수로 식별
11. **UC-12** 업로드 1건 삭제 — DB 행 + Storage 원본이 **함께** 사라진다
12. **UC-13** 실패한 분석 재시도 — 최대 2회
13. **UC-14** 결제·구독 관리 (Polar Customer Portal)
14. **UC-15** 구독 상태 동기화 — 서명 검증 웹훅이 갱신·실패·취소를 멱등 반영
15. **UC-16** 구독 종료 후 열람 — 유료 화면은 다시 잠기고, 무료 화면과 데이터는 남는다

## 구독 및 기능 게이트

**횟수제가 아니라 기능 게이트다.** 분석 횟수를 세지 않는다.

| | 무료 | 유료 (Pro) |
|---|---|---|
| 업로드·분석 | 제한 없음 | 제한 없음 |
| 절세 추정액 | ✓ | ✓ |
| 인사이트 | 상위 3개 | 전체 |
| 거래별 분류 내역 | ✗ | ✓ |
| 시계열 대시보드 | ✗ | ✓ |
| 세무사 전달용 다운로드 | ✗ | ✓ |

사용자가 **"내 돈 얼마"라는 자기 숫자를 본 뒤에** 결제하게 하는 구조다. 랜딩 페이지가 혼자 설득을 짊어질 필요가 없다. 다운로드를 막았기 때문에 무료로 일을 끝낼 수는 없다.

**게이트는 서버에서 판정한다.** 잠긴 데이터를 클라이언트로 보내고 CSS로 가리는 방식은 게이트가 아니다.

- **상품**: Polar 단일 상품, 월 구독. 다단계 요금제를 만들지 않는다
- **가격**: 월 ₩9,900 (가설. Polar 상품 설정이 청구 source of truth). 게이트 모델로 바뀌면서 횟수 기반 근거가 사라졌으므로 **재검증 대상**
- **결제수단·영수증·취소 UI는 만들지 않는다** — Polar Customer Portal에 위임

### 구독 종료 후 접근 정책

구독이 끝나는 사유(자발적 해지, 결제 실패, 만료)와 무관하게:

- **데이터를 지우지 않는다.** 데이터를 지우는 것은 사용자의 삭제 요청·계정 삭제·90일 만료뿐이다
- **유료 화면이 다시 잠긴다** — 전체 분류 내역·시계열·다운로드. 무료 기간에 만든 것이든 유료 기간에 만든 것이든 동일하다
- **무료 화면은 과거 분석 전부에 대해 계속 열린다** — 절세 추정액과 상위 3개 인사이트
- **이미 다운로드한 파일은 회수하지 않는다.** 사용자 손에 있는 파일이다
- **재구독하면 즉시 전부 다시 열린다.** 데이터를 지우지 않았으므로 재분석이 필요 없다
- `past_due` 동안은 Pro를 유지한다 — Polar가 `unpaid`/`revoked`를 보낼 때 잠근다

> **결정 근거**: 게이트는 화면에 걸리는 것이지 데이터에 걸리는 것이 아니다. 구독 종료를 데이터 파기로 처리하면 재구독 사용자에게 재분석을 강요하고(우리 원가), 세무 자료를 잃은 사용자에게 신뢰를 잃는다.

## 데이터 처리 원칙

- **LLM에 개인식별정보를 보내지 않는다.** Anthropic으로 나가는 것은 ① CSV 상위 20행(헤더 구조 판별용) ② 가맹점 상호명 문자열 배열, **이 둘뿐**이다. 금액·날짜·카드번호·사용자 식별자는 전송 대상이 아니다. "누가 언제 얼마를 썼는지는 서버 밖으로 나가지 않는다"를 처리방침에 그대로 쓸 수 있다
- **원본은 90일 후 자동 삭제한다.** 비공개 버킷에 암호화 저장하고, 계정 삭제 시에는 즉시 전량 파기한다
- **카드번호·승인번호는 정규화 단계에서 제거하고 저장하지 않는다**
- **합계·구성비·추이·절세 추정액은 서버가 계산한다.** 모델에게 산술을 시키지 않는다
- **로그에 PII를 남기지 않는다** — 가맹점명·카드번호·CSV 내용·웹훅 원문 body 금지. 실패 시 에러 코드와 행 수만 남긴다
- `merchant_dictionary`·`csv_format_mappings`는 **전역 공유 자산**이다. 상호명과 헤더 구조는 개인정보가 아니며, 사용자가 늘수록 히트율이 올라 분석 원가가 내려간다

## 분류 실패 처리

**분류 실패에는 두 층이 있고, 섞으면 안 된다.**

| 층 | 무엇 | 결과 |
|---|---|---|
| **파이프라인 실패** | 파싱 불가, 컬럼 매핑 판정 실패, LLM 거부·응답 절단, 상류 오류 | 업로드 전체가 `failed` + `error_code`. 재시도 가능(최대 2회) |
| **개별 거래 판정 불확실** | 사전에 없고 모델도 업종을 특정하지 못한 상호 | 해당 거래만 **`애매`**. 분석은 `completed` |

**개별 거래의 분류 실패가 분석 전체를 실패시키지 않는다.** 이것이 분류를 2값이 아니라 `사업 경비 / 개인 지출 / 애매` **3값**으로 둔 이유다.

- **`애매`는 절세 추정액에서 제외한다.** 추정액은 항상 보수적인 하한이어야 한다 — 세무에서 과대 추정은 사용자에게 리스크를 넘기는 행위다
- 리포트 상단에 **"애매 n건"을 숨기지 않고 표시**한다. 사용자가 그 n건을 세무사에게 따로 물을 수 있어야 한다
- `애매` 비율이 비정상적으로 높으면(예: 30% 초과) 분류가 아니라 **컬럼 매핑이 틀렸을 가능성**을 먼저 안내한다
- 오분류 **수정 UI는 MVP 제외** — 사용자가 고친 값을 전역 사전에 반영할지 판단할 근거가 아직 없다

## 중복 거래 처리

여러 카드·여러 기간 파일을 올리는 제품이므로 중복은 예외가 아니라 기본 상황이다. **세무 자료에서 과대계상은 누락보다 위험하다.**

- **동일 파일 재업로드**: 파일 내용 해시가 같으면 접수 단계에서 거절하고 기존 분석으로 안내한다 (무손실·명확)
- **파일 간 거래 중복**: `거래일자 + 금액 + 정규화 상호명`의 지문으로 감지한다. 중복 건은 **저장하되 집계에서 제외 표시**한다 — 삭제하지 않는다. 같은 날 같은 가맹점 같은 금액의 진짜 별개 거래(커피 2잔)가 존재하므로 자동 삭제는 데이터 손실이다
- 리포트에 **"중복 제외 n건"을 표시**한다. 집계에서 조용히 빼지 않는다
- **취소·부분취소 거래**: 금액 부호를 보존해 정규화하고 집계에서 상계한다. 취소 행을 버리면 합계가 틀어진다
- 중복 판정을 사용자가 뒤집는 UI는 **MVP 제외**

## 제약

- **파일**: CSV only (XLSX·PDF는 명확한 거부 + 변환 안내), 2MB / 3,000행 이하
- **분석 시간**: 사전 히트 시 수 초, 미스가 많은 초기에는 60–180초
- **법적 포지셔닝**: 세무 자문이 아니라 **경비 후보 정리 도구**다. 리포트 문구는 "경비 처리 가능성이 높은 항목", "예상 절감액(참고용)"으로 쓰고, 화면·PDF·약관에 "본 서비스는 세무 자문이 아니며 최종 판단은 세무대리인과 상의하십시오"를 명시한다. 단정적 지시("경비 처리하세요", "환급받으세요")는 쓰지 않는다

## MVP 제외 사항

- 마이데이터·오픈뱅킹 자동 연동 (CSV 수동 업로드만)
- 분류·중복 판정 수정 UI
- 팀·법인카드 다인 계정 및 권한 관리
- 세금 신고서 자동 작성·제출
- Google 외 소셜 로그인 (카카오 포함)
- 다단계 요금제
- 원본 재다운로드 · 계정 자동 삭제 (요청 시 수동 처리)

## 미해결 (후속 결정 필요)

- **무료 남용 방어**: 횟수제를 버렸으므로 무제한 무료 분석이 열려 있다. 원가가 낮다는 전제(ADR-001)가 실측으로 깨지면 방어 장치가 필요하다
- **Pro 가격**: ₩9,900은 횟수제 시절 가설이다. 게이트 모델에서 재검증해야 한다
- **전역 사전 오염**: 잘못된 항목 1건이 전 사용자에게 전파된다. 신뢰도·출처·롤백 설계가 없다

## 디자인

- 신뢰형 미니멀. 사용자에게 카드 명세서를 요구하는 제품이므로 **화면의 신뢰도가 곧 전환율이다.** 금융·세무 서비스의 시각적 관습을 따르고 장식을 최소화한다
- 무채색 기반 + 포인트 컬러 1가지(딥블루 계열). 데이터 밀도가 높은 대시보드
- 금액은 `font-variant-numeric: tabular-nums`로 자릿수를 맞춘다
- 라이트/다크 양쪽을 지원한다
- **빈 상태를 먼저 설계한다** — 업로드 0건인 대시보드가 다음 행동(업로드 안내 · 카드사별 CSV 내려받는 법)을 알려주지 못하면 실패다. 데이터가 없을 때 빈 차트를 그리지 마라
- **잠긴 상태를 설계한다** — 유료 영역은 "결제하세요"가 아니라 *무엇이 잠겨 있는지*를 보여줘야 한다. 잠금 화면이 곧 결제 페이지다
- 거래 3건뿐이면 도넛·추이 대신 표로 대체한다
- 모바일에서 차트는 컨테이너 폭 기준, 표는 가로 스크롤 컨테이너 안에 둔다
