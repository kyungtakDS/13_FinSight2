# Architecture Decision Records

## 철학

MVP 속도 최우선. 외부 의존성 최소화. **작동하는 최소 구현을 고른다.**
영리한 장치가 그것을 수습하는 장치를 여럿 낳으면, 영리한 쪽을 버리고 평범한 쪽을 택한다.

---

### ADR-001: Supabase 단일 백엔드
**결정**: Auth · Postgres · Storage를 모두 Supabase로.
**이유**: 인증·DB·파일 저장이 한 SDK와 한 권한 모델(RLS) 안에 들어온다.
**트레이드오프**: 벤더 종속. RLS를 우회하는 service role 경로가 생겨 규율이 필요하다 (ADR-004로 완화).

### ADR-002: CSV 전문을 Claude에 전달하되 합계는 서버가 계산
**결정**: 모델 출력은 *행별 카테고리 · 구독 후보 · 인사이트*까지. 합계·구성비·추이는 서버 TypeScript가 원본 금액으로 계산한다.
**이유**: 산술을 모델에 맡기면 틀려도 그럴듯해서 검출되지 않는다. 카드 명세서 앱에서 합계 오류는 치명적이다.
**트레이드오프**: 집계 코드를 직접 짜야 하고, 모델 출력 배열과 원본 행의 인덱스 정합성을 검사해야 한다.

### ADR-003: Google OAuth 단독
**결정**: 이메일/비밀번호·매직링크를 만들지 않는다.
**이유**: 비밀번호 재설정·이메일 인증 흐름이 통째로 사라진다.
**트레이드오프**: Google 계정이 없는 사용자를 놓친다. 무료 한도를 새 계정으로 우회하기 쉽다 (MVP 규모에서 감수).

### ADR-004: mock-first — 키 없이 전체 검증이 통과해야 한다
**결정**: 외부 호출을 `services/`·`lib/supabase/` 뒤로 격리하고 테스트는 SDK를 mock한다. 환경변수 검증은 lazy.
**이유**: Stop 훅이 매 세션 종료마다 `lint && build && test`를 돌린다. 테스트가 키를 요구하면 **모든 step이 연쇄 실패**한다.
**트레이드오프**: mock이 실제 SDK와 어긋날 수 있다 → 검토 지점의 수동 E2E로 메운다.

### ADR-005: 분석은 비동기 잡 — `after()` + `maxDuration`
**결정**: 접수 라우트가 202를 반환하고 `after()`가 같은 인스턴스에서 처리를 잇는다. 별도 워커·큐 인프라를 두지 않는다.
**이유**: 60–180초를 HTTP 요청으로 붙잡을 수 없다. 큐를 도입하면 의존성과 운영 대상이 늘어난다.
**트레이드오프**: 처리는 여전히 함수 수명 안이다 — 비동기화가 해결하는 것은 **브라우저와의 결합**이지 서버 실행 시간이 아니다. `after()`가 죽으면 행이 `processing`에 남으므로 조회 시점 회수가 필요하다.

### ADR-006: 실패는 한도를 차감하지 않는다
**결정**: `failed`는 한도 집계에서 제외한다.
**이유**: 우리 잘못으로 실패한 분석이 무료 횟수를 먹으면 그 사용자는 돌아오지 않는다.
**트레이드오프**: 재시도 비용이 무료가 되므로 `retry_count` 최대 2로 상한을 둔다.

### ADR-007: MVP는 CSV only
**결정**: XLSX·PDF는 파싱하지 않고 명확한 거부 문구 + 변환 안내를 준다.
**이유**: 한국 카드사가 XLSX를 주는지는 아직 모르고, 파서를 하나 더 만드는 비용이 크다.
**트레이드오프**: 최대 마찰 지점을 의도적으로 남긴다. 거부 문구가 다음 행동(엑셀 → CSV 저장)을 알려주는지가 A-2의 검토 기준이 된다. 사용자 피드백을 보고 재판단.

### ADR-008: Polar 구독 결제를 MVP에 포함
**결정**: Free 월 3회 / Pro 월 20회, 초기 가격 ₩9,900. 결제수단·영수증·취소 UI는 직접 만들지 않고 Polar Customer Portal에 위임.
**이유**: "분석이 쓸 만한가"와 "돈을 내는가"를 함께 검증한다.
**트레이드오프**: 웹훅 인프라(서명·멱등·순서)가 통째로 들어온다. 가격·상한은 사용량 실측 전이라 후속 ADR로 조정한다.

### ADR-009: Pro 권한의 source of truth는 서명 검증된 웹훅을 반영한 DB 상태
**결정**: success URL·checkout ID·클라이언트 응답은 권한 근거가 아니다. `profiles.plan`은 검증된 웹훅 transaction 안에서만 바뀐다.
**이유**: 리다이렉트 파라미터로 권한을 열면 누구나 Pro가 된다.
**트레이드오프**: 웹훅 지연 동안 "결제했는데 아직 Free"인 구간이 생긴다 → `/billing/success` 폴링과 안내 문구로 메운다.

### ADR-010: 웹훅 멱등 기록과 구독·plan 반영은 한 transaction
**결정**: `webhook_events` INSERT와 `subscriptions` upsert와 `profiles.plan` 변경을 하나의 transaction으로 묶는다. 성능을 이유로 분리하지 않는다.
**이유**: 분리하면 크래시 시 이벤트가 *처리됨*으로 기록된 채 반영되지 않고, Polar의 재전송마저 멱등 검사에 걸려 버려진다 → 결제는 성공했는데 영원히 Free.
**트레이드오프**: transaction이 길어진다. MVP 트래픽에서는 무시할 수준.

### ADR-011: 한도는 두 겹 — 사전 read(비용)와 원자적 함수(정합성)
**결정**: Storage 업로드 **전**의 값싼 한도 read와, advisory lock 안의 원자적 접수 함수를 **둘 다** 둔다. 역할을 합치거나 한쪽만 두지 않는다.
**이유**: 사전 read만 두면 동시 요청이 한도를 넘고, 원자적 함수만 두면 소진된 사용자도 매번 파일을 끝까지 업로드한 뒤 거절당한다("비용 태우고 거절하지 않는다"를 어긴다).
**트레이드오프**: 검사가 두 번이다. 대신 부분 유니크 인덱스로 동시성을 막던 초기안의 **계정 영구 잠금 버그**와 그 수습(이중 회수·409 변환·행 재사용 강제)이 전부 사라졌다.
